What: a firewall is one box with an address in every network it connects. Here it is {{ fw.interface_ip if fw and fw.interface_ip and fw.kind != 'none' else "not known yet (the field above is empty: SegCheck fills it in from the firewall's first log, or you type it)" }}; in the other networks it has other addresses (often the .1 of each, but not always).

Why: ISO/IEC 27002 8.20 and NIST SC-7 say staff networks must not be able to reach the firewall's own admin services (SSH, web admin, SNMP). Many firewalls answer them on every address, so testing only the nearest one can miss a real finding.

What it does, and does not do: only the Step 4 standard Firewall management plane protection tries these addresses, and only on the admin ports. It does not change how the firewall's logs reach this PC (3b), and the other standards never treat these addresses as servers.

SegCheck never logs in to the firewall or changes it; it only listens. To prove that a block really happened, whoever manages the firewall (at a client: their network team) sets it once to send its log lines to this PC. This PC's address and port, {{ ip }}:{{ port }}, are already filled in below: copy them as they are.

  1. pfSense: Status → System Logs → Settings. Tick Send log messages to remote syslog server. Remote log servers: {{ ip }}:{{ port }}. Remote Syslog Contents: tick Firewall Events. Log message format: BSD (RFC 3164). Save.
    OPNsense: System → Settings → Logging / targets → +. Transport UDP(4), Applications filter (filterlog), Hostname {{ ip }}, Port {{ port }}, RFC5424 off. Save and Apply.
  2. On the rules that block traffic from this network, tick Log packets that are handled by this rule. In pfSense also tick Log packets matched from the default block rules (Status → System Logs → Settings). Apply.
  3. On this PC: if Windows asks whether Python may receive network traffic, choose Allow. When the first log arrives, the status above turns green (Logs arriving).
  1. Send FortiGate's logs to this PC. In the FortiGate CLI (or Log & Report → Log Settings → Remote Logging → Syslog, then set the port in the CLI):
    config log syslogd setting
      set status enable
      set server "{{ ip }}"
      set port {{ port }}
      set mode udp
      set format default
    end
  2. Log every decision between these networks. Policy & Objects → Firewall Policy: on each policy between this PC's network and the targets, set Log Allowed Traffic to All Sessions. Also log what the implicit deny blocks: config log setting → set fwpolicy-implicit-log enable → end. For connections to the FortiGate itself (firewall-management check): config log setting → set local-in-deny-unicast enable → end.
  3. On this PC: if Windows asks whether Python may receive network traffic, choose Allow. When the first log arrives, the status above turns green (Logs arriving).
  1. Send the ASA's logs to this PC. In configuration mode, using the name of the interface that faces this PC (e.g. inside):
    logging enable
    logging timestamp
    logging trap informational
    logging host inside {{ ip }} udp/{{ port }}
  2. Log the access-list decisions. Denies by an access list are logged by default (message 106023). To also log what is permitted, add log to the permit entries, e.g. access-list INSIDE_IN extended permit tcp any host 10.30.0.10 eq 443 log.
    Firepower (FTD) managed by FMC: Devices → Platform Settings → Syslog → Syslog Servers: add {{ ip }}, UDP {{ port }}; then in the access control policy, on each rule tick Log at Beginning of Connection with Syslog Server as destination.
  3. On this PC: if Windows asks whether Python may receive network traffic, choose Allow. When the first log arrives, the status above turns green (Logs arriving).
  1. Send Sophos Firewall's logs to this PC. System services → Log settings → Add (syslog server): name SegCheck, IP {{ ip }}, port {{ port }}, facility DAEMON, severity Information, format Device standard format. Save, then in the log list tick Firewall (firewall rules, invalid traffic) for this server.
  2. Log each rule's traffic. Rules and policies → Firewall rules: open each rule between this PC's network and the targets and tick Log firewall traffic. Dropped traffic that matches no rule is logged as the default drop.
  3. On this PC: if Windows asks whether Python may receive network traffic, choose Allow. When the first log arrives, the status above turns green (Logs arriving).
  1. Send the router's firewall log to this PC. In the terminal (or System → Logging in WinBox):
    /system logging action add name=segcheck target=remote remote={{ ip }} remote-port={{ port }}
    /system logging add topics=firewall action=segcheck
  2. Log the forward rules, with a name SegCheck can read. Drop rules: /ip firewall filter set [find chain=forward action=drop] log=yes log-prefix="SEGCHECK-DROP". Allow rules (optional, name each one): e.g. /ip firewall filter set 5 log=yes log-prefix="SEGCHECK-ACCEPT-staff-web". For connections to the router itself (firewall-management check), the input chain too: /ip firewall filter set [find chain=input action=drop] log=yes log-prefix="SEGCHECK-DROP".
  3. On this PC: if Windows asks whether Python may receive network traffic, choose Allow. When the first log arrives, the status above turns green (Logs arriving).
  1. Make the firewall write a log line for every packet it blocks. On the Linux firewall, as root, add this rule just before its final "drop" rule:
    iptables -A FORWARD -j LOG --log-prefix "SEGCHECK-DROP "
    (with nftables: nft add rule inet filter forward log prefix "SEGCHECK-DROP ", before the drop)
    Also for connections to the firewall itself (used by the firewall-management check): add the same rule to the INPUT chain, just before its final drop: iptables -A INPUT -j LOG --log-prefix "SEGCHECK-DROP " (nftables: nft add rule inet filter input log prefix "SEGCHECK-DROP ").
  2. Send those log lines to this PC. On the firewall, create the file /etc/rsyslog.d/90-segcheck.conf containing the line kern.* @{{ ip }}:{{ port }} (meaning: send firewall messages to {{ ip }}, port {{ port }}), then restart the log service: systemctl restart rsyslog.
  3. On this PC: if Windows asks whether Python may receive network traffic, choose Allow. When the first log arrives, the status above turns green (Logs arriving).
